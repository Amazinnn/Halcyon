# 风险清单 v0（首轮）

> 对应设计稿 §25 第 10 条要求：每条不确定项写明风险、退路与验证方法。2026-08-05。

| # | 风险 / 不确定项 | 退路 | 验证方法 |
|---|---|---|---|
| 1 | WebView2 透明窗口在部分 GPU/驱动组合下渲染异常 | 改不透明圆角窗口；或 DWM/合成器检测后降级 | 目视确认 + 多机/多 GPU 回归；截图基线 |
| 2 | 200% DPI 下 `inner_size` 逻辑/物理尺寸语义不直观（440→外框 453×716） | 明确使用 `PhysicalSize`；启动时读取缩放因子按需换算 | M0 在 100/125/150/200% 各档实测窗口与桌面布局 |
| 3 | 事件总线广播 Lagged（消费者慢导致丢事件） | 增大 channel 容量；关键状态（如当前 agent 状态）前端启动时全量拉取 | 长时间运行 + 高频事件压测，观察丢包计数 |
| 4 | WebView2 运行时版本差异 | 记录运行时版本；跟随 Tauri/WebView2 更新做回归 | 升级后重跑任务 C 矩阵 |
| 5 | 前台探针在锁屏/远程会话/安全桌面下行为不确定 | 低频心跳兜底 + 事件补齐；不做高频轮询 | 锁屏、休眠、RDP 场景实测 |
| 6 | Windows 虚拟桌面依赖未公开 COM 接口（推迟 M6） | 保持 Overlay 模式；失败自动回退 | 每次 Windows 大版本升级做兼容测试 |
| 7 | 多显示器支持未验证（本机单屏） | 主屏 Overlay + 记录辅助屏状态 | 外接显示器或虚拟显示器驱动实测 |
| 8 | 全屏应用与置顶小窗（宠物/音乐）层级冲突 | 全屏应用检测后自动收缩小窗（V1 未实现，列入 M2） | 手动打开全屏应用观察 |
| 9 | SQLite 多模块并发写（探针 + 未来计时/统计） | 后端 Mutex 串行化；后续启用 WAL | 压测 + 长时间运行观察锁等待 |
| 10 | `@focus/event-schema` 用 `file:` 依赖（npm 复制而非链接） | 改为 `link:` 或 npm workspaces | 修改 schema 后验证 apps/desktop 同步 |
