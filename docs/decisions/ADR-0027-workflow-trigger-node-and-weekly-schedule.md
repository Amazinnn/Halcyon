# ADR-0027：工作流触发节点与每周计划

- 状态：已接受（2026-08-10）
- 关联：需求 #83、ADR-0020（Agent 日程工具）、ADR-0021（运行语义）

## 背景

工作流已经是日程工具，但触发条件只散落在元数据中，画布没有可见入口；计划也缺少每周固定时刻。用户需要能看见并编辑“手动、间隔、每日、每周”四种触发方式，而不把日程工具重新扩展为通用自动化平台。

## 决策

1. **画布左侧固定一个虚拟触发节点。**它不可连接、不可拖动、不可删除，且永不写入 `nodes` 或 `edges`。它只反映并打开工作流元数据的触发编辑器，不是引擎执行节点。
2. **计划保持四种模式。**手动不进入调度器；间隔按分钟重排；每日使用本地 `HH:MM`；每周使用单个星期和本地 `HH:MM`。每周的内部星期值为周一 `0` 至周日 `6`。
3. **每周字段属于工作流 JSON 元数据。**`weeklyDay` 与 `weeklyTime` 与既有 `scheduleType`、`intervalMinutes`、`dailyTime` 同级保存；scheduler 在保存、运行完成或守卫跳过后重新计算 `nextRunAt`，下一次必须严格晚于当前本地时间。
4. **不改变图执行引擎。**触发节点不产生边、不进入运行记录、不增加动作节点、模板、看板、历史会话或通用自动化能力。已有 `focus_end` 与 `supervision_alert` 事件触发语义不变。

## 影响

- 工作流列表与画布都显示简短触发标签，例如“定时 · 周一 09:00”；前端只把实际动作节点和边序列化。
- 模型验证拒绝非法星期或时间；调度器继续使用本机时区计算下一次本地执行。
- 自动回归覆盖每周下一次运行、scheduler 重排、虚拟节点不持久化和标签渲染；本周实际触发仍需按 Eval 做人工验收。
