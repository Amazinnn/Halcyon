# ADR-0024：Agent 对话与工作流闭合

- 状态：已接受（2026-08-09）
- 关联：需求 #76–#78；ADR-0020（工作流作为 Agent 日程工具）、ADR-0022（宠物=Agent）

## 背景

M5 已具备宠物=Agent、Codex 运行时和工作流 JSON/CLI 通道，但正式对话是否真实、聊天是否简洁，以及工作流最终结果如何进入对话仍有缺口和过时 UI 语义。用户要求保持极简、不要快捷动作，并以真实 Agent 对话和工作流分配作为验收门槛。

## 决策

1. **正式桌面只使用真实 Provider**：Codex 不可用时直接显示实际错误；Mock 只允许测试注入，正式路径绝不自动回退。
2. **聊天极简**：仅保留 Agent 选择、连接/生成状态、消息、停止生成和输入框。新会话、选项、快捷动作、技能芯片、工作区编辑、自动化清理和工具过程条不留在聊天窗口。
3. **工作流是统一日程列表**：列表固定显示全部工作流，不按角色筛选，也不提供复制、迁移或归属操作。新工作流默认不绑定 Agent；既有数据保持原状。
4. **节点目标与展示**：新 Agent 节点默认当前聊天 Agent，用户仍可改目标。运行过程的原始流式与完成事件不进入聊天；仅当 `showResult` 为真时，以**恰好一条**「日程 · 名称」来源消息把最终文本回流到目标 Agent 的聊天与宠物泡泡。`showInitial`、`showThinking` 不再是工作流节点的展示选项。
5. **直接对话独立**：直接聊天保留它自己的完整对话语义；工作流来源结果只是进入目标 Agent 聊天的一条最终结果，不混入过程。
6. **冻结边界不扩张**：工作流继续是 ADR-0020 定义的日程工具，不新增节点、模板、看板、历史会话或通用自动化平台。

## 影响

- `workflow:changed` 驱动统一列表刷新；`workflow:agent_result` 只承载允许展示的一次最终结果。
- 真实验收必须让当前宠物与真实 Codex 对话，并由它经 focus-cli 创建、读取、更新、运行、删除唯一命名的临时手动工作流。Mock 成功不构成验收。
